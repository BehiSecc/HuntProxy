# HuntProxy v0.3.0

Run `HuntProxy update`. Projects, history, cookie identities and browser profiles carry over; there is no schema change from v0.2.0.

## Upgrading

- **From v0.1.1:** run `HuntProxy stop`, then `HuntProxy update`, then reconnect your MCP client.
- **Docker:** rebuild the image, recreate the container with the same data volume and the supplied seccomp profile, and reconnect `docker exec` MCP clients.
- **Ubuntu 24.04+:** if AppArmor blocks Chromium's sandbox, browsers still start without it and `HuntProxy doctor` says so. Add the AppArmor profile from the README to keep the sandbox.
- A restart interrupts active browsers and running jobs; collect any in-memory plugin results first.

## Highlights

- **Browser that looks like a real Chrome:** persistent workspaces run Chromium natively with its own version, brands and platform metadata. Set `HUNTPROXY_BROWSER_HEADLESS_COMPAT=false` for the previous Playwright headless mode.
- **Matching network fingerprint:** proxy, Reply and WebSocket traffic use a Chrome 153 TLS/HTTP profile that matches the bundled browser, and browser headers keep their original order and values.
- **Browser runtime:** Playwright 1.63.0 with Chromium 153. Profiles saved by v0.2.0's Chromium 156 keep their cookies and site storage.
- **Quieter History:** Chrome's own background requests (sign-in and push registration) are forwarded but no longer saved.
- **Faster project export:** exports copy only the selected project instead of the whole database.
- **Plaintext WebSocket tunnels** through the proxy are now intercepted, and zstd responses are decoded.

## Fixes

- Browser back/forward no longer time out.
- `browser install` finds the private Node runtime created by the installer.
- Clearer errors for Chromium startup failures and unknown browser sessions; complete CLI help text.
- `projects` list returns a compact summary, so large installations fit MCP clients.
- HAR and project export files are created readable only by you; the HAR export description now says that sanitizing removes credential headers but keeps URLs and bodies.
- The web UI shows the real reason when an IP rotation job fails.

## Compatibility

- v0.2.0 uses the same database schema, so rolling back the executable keeps projects readable. Keep a full backup of `~/.huntproxy` before updating if you might need to roll back browser profiles.
- MCP tool descriptions changed; clients that cache tool lists should reconnect once.
