# HuntProxy v0.4.5

Run `HuntProxy update`. Your data carries over and migrates automatically, and the upgrade rewrites how headers are stored, about a minute per GB of database.

If `~/.huntproxy/huntproxy.db` is larger than about 5 GB, update with the install script instead:

```sh
curl -fsSL https://raw.githubusercontent.com/BehiSecc/HuntProxy/master/install.sh | bash
```

The v0.4.0 updater stops after 15 minutes. The install script waits as long as the upgrade makes progress. If `HuntProxy update` runs out of time, it stops before its limit, changes nothing, and tells you to use the install script.

## New

- **Smaller database:** each distinct header name and value is stored once, and spooled bodies are compressed. The upgrade compacts the file once; a 19 GB database shrank to 10 GB.
- **Request limits per project:** `projects` action `set_limits`, or the Request limits panel, sets the request rate and concurrency that Reply, Fuzzer, the crawler and extensions share. Changes apply at once, including to running fuzz jobs.
- **Fuzz case timeout:** a fuzz template takes `request_timeout_ms`, so a slow endpoint fails its case instead of holding a request slot.
- **`fuzz_manage get` can wait** up to 30 s for the job to end (`wait_ms`), instead of being polled.
- **Body search reads through `Content-Encoding`:** `response:~` finds text in gzip, brotli and zstd responses.
- **Faster fuzzing:** a job's cases share one connection pool, and each case writes less to the database.

## Fixes

- Fuzzer `§markers§` in `body_text`, `body_json` and `body_params` work. Before, every case failed with "provide only one of body_override, body_text, body_json, or body_params".
- `fuzz_start` works with OpenAI Codex, which answered HTTP 500 to its schema. Thanks to whiskeykilo (#3).
- Browser: a slow call holds up only its own session, point clicks report what they hit, drags to a point never scroll, and an aborted session whose browser will not close gets a new worker.
- `browser_input` typing adds to the end of a field's text, and leaves sliders and radio buttons as they were.
- `job_results`, fuzz result and `websocket_manage` pages no longer skip items at the output budget; long WebSocket payloads can be read whole.
- HAR import no longer fails with "database is locked" while other writes run.
- The web UI no longer shows, and saves, the previous project's settings when a project fails to load.

## Note

- **Disk space:** the upgrade checks for free space first, about 60% of the database size, and refuses without changing anything if there is too little. Upgrades keep only the newest database copy in `runtime/migration-backups`.
- **Connections:** cases of one fuzz job now reuse connections even when they vary `Cookie` or `Authorization`, like Burp Intruder. Separate jobs and Reply keep their own.
- v0.4.0 can't open the upgraded database. To roll back, restore the update's restore point with the previous executable.
