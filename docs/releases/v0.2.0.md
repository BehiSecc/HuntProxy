# HuntProxy v0.2.0

This is a substantial pre-1.0 minor release. Existing saved projects migrate on opening, and v0.1.1 project bundles import through the same workflow. Users do not need to export their projects again.

## Update experience

The managed browser now requires **macOS 14 or later**. On older Macs, upgrade macOS before updating HuntProxy. Linux support covers Debian 12/13 and Ubuntu 22.04/24.04/26.04 on x86_64 and ARM64.

`HuntProxy update` on native v0.2 installations and newer verifies the release checksum and version, prepares the matching browser worker, pinned Playwright SDK, Chromium, and official plugins, then replaces the executable. It coordinates daemon startup and direct database commands, stops a running daemon, and restarts it after activation. The native installer uses the same transaction. Docker deployments update by rebuilding and recreating the container with the same data volume; their `docker exec` MCP connections must reconnect afterward.

The updater preserves the database and configuration plus packages that the target release may change before preparing it. Normal failures roll back. A durable private journal recovers interrupted preparation before the next project open. The latest managed restore point is retained; older validated update restore points are pruned. Schema upgrades preserve an additional private database backup.

The v0.2 MCP bridge follows the daemon's current tool definitions and sends `notifications/tools/list_changed` after a later version change. Clients supporting that standard notification can refresh capabilities on the existing connection. Passive catalog checks do not start the daemon or keep it alive, and the bridge retains its latest validated catalog while the daemon is stopped. Tool calls are dispatched once.

The published **v0.1.1 updater still requires stopping HuntProxy before updating and reconnecting the MCP client afterward**. Its replacement binary automatically prepares the new runtime and plugins on first startup. That existing binary cannot acquire the new update behavior before it has been replaced.

Official packages matching a trusted released fingerprint update automatically. Modified packages and custom plugin folders remain intact. A preserved Racer older than 0.6.4 is blocked with a compatibility error because it cannot interpret the new response evidence reliably. Other custom packages should be tested against the new host.

Active browser sessions and running jobs are interrupted by a restart. Saved project data, history, findings, drafts, cookie identities, browser cookies and site storage, configuration, and the existing CA remain available. Memory-only job results and analysis checkpoints do not survive; collect them before updating.

## Capabilities since v0.1.1

- Named persistent browser profiles support separate saved workspaces and explicit named cookie seeds. The dashboard exposes cookie profiles and the new browser actions.
- Structured browser actions cover uploads, page and element inspection, tab management, bounded event metadata, scrolling, screenshots, and same-origin browser requests.
- Reply and Fuzzer drafts can select named or anonymous request identities.
- Raw transport evidence retains received responses alongside completion state and connection errors.
- Plugin execution summaries describe returned, skipped, unobserved, and incomplete evidence. The bundled catalog includes Auth Analyzer 1.4.2, Racer 0.6.4, and Request Smuggler 1.4.9.

## Quality and compatibility fixes

- The managed browser uses Playwright Core 1.64.0 and Chromium 156. Saved browser cookies and site storage carry over automatically; the obsolete managed browser is replaced on preparation. Explicit browser overrides remain supported.
- Sanitized project exports remove both default and named cookie secrets. Full bundles retain named identities on import.
- Legacy bundles are verified before migration. Failed imports clean their private staging data, and exports replace their destination atomically.
- Historical browser sessions keep unknown profile provenance instead of being incorrectly labeled as a persistent default identity.
- Browser event waits no longer hold the shared worker for their whole timeout. CDP handoff restores background tabs, active selection, and per-tab session storage.
- Page analysis retains response status, completion, MIME type, and effective URL. Failed HTML responses are excluded from JavaScript analysis, and rewritten child resources resolve against the correct base.
- Browser actions publish action-specific MCP input schemas. Configured worker paths survive configuration serialization and respect environment overrides.
- Plugin planning and analysis recheck cancellation and their deadline when returning, including short scripts.
- Shutdown closes project event streams and bounds server draining. Advisory locks retain their inode across replacements.
- HTTP/2 and TLS dependencies include the advisory fixes for [h2](https://rustsec.org/advisories/RUSTSEC-2026-0258.html) and [Rustls](https://rustsec.org/advisories/RUSTSEC-2026-0285.html). The unused, unmaintained PEM dependency is removed, and release CI requires dependency and license checks.
- Release checks include serialized real Chromium tests, an upgrade from the verified v0.1.1 binary, and unpublished candidate builds for all four platforms. Tag builds create a draft release for review.
- Release archives include generated license and copyright notices for the locked Rust dependencies and their vendored components. CI checks their completeness and the legacy updater's archive size limits.

## Compatibility notes

The legacy default browser directory remains valid. Ordinary persistent starts resume the saved browser jar; a named cookie profile is applied only when explicitly selected. Returning from CDP creates a new runtime generation, so clients should list tabs and begin new event cursors before continuing.

Sanitized exports omit credentials and browser storage intentionally. Full exports and private backups contain sensitive project data. An older executable cannot open schema 15; the updater refuses an incompatible legacy downgrade. Reverting only the executable is insufficient after a schema upgrade.

Release archives retain exactly `HuntProxy` and `LICENSE`, including third-party notices in the latter, so the published v0.1.1 updater can still extract them.
